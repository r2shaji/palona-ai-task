# Palona AI Shop

An e-commerce platform with AI-powered product recommendations and search capabilities.

## Features

*   **AI Chatbot:**
    *   **Natural Language Understanding:** Parses user queries to understand intent, identify product categories (entities), and extract descriptive attributes (e.g., color, material, style).
    *   **Intent Recognition:** Employs a hybrid approach:
        *   **Heuristic Matching:** Quickly identifies common intents (like searching for best-sellers or specific categories) using keyword analysis for faster responses.
        *   **OpenAI Integration:** Leverages OpenAI's GPT models for deeper understanding and accurate intent/entity/description extraction for more complex or nuanced queries.
    *   **Dynamic Response Generation:** Provides informative text responses generated by OpenAI, contextualized to the user's query (e.g., style advice, fabric information) before showing products.
    *   **Intelligent Product Search:** Searches the product database based on extracted category and description. Handles cases where exact matches aren't found by suggesting alternatives within the same category.
    *   **Alternative Category Suggestions:** If a user asks for a category not carried (e.g., "jackets"), the chatbot identifies the closest valid category (e.g., "T-Shirts") and suggests relevant products from that alternative category.
    *   **Subjective Qualifier Handling:** Differentiates between objective descriptions and subjective terms, ignoring the latter for search filtering to provide broader results for qualitative requests.
*   **Image-Based Search:**
    *   **CLIP Feature Extraction:** Uses the CLIP model to generate vector embeddings for product images.
    *   **FAISS Indexing:** On startup, builds a FAISS index containing image features for the top 10 most popular products from each category, enabling rapid similarity searches.
    *   **Similar Product Recommendations:** Allows users to upload an image to find visually similar products in the catalog.
*   **Architecture:**
    *   **Dockerized Services:** The application can be fully containerized using Docker and Docker Compose (configuration provided in `docker-compose.yml`), consisting of:
        *   `palona-frontend`: React-based user interface.
        *   `palona-backend`: Flask API server handling business logic, AI integration, and database interaction.
        *   `mysql`: MySQL database storing product, category, and brand information.
    *   **Database:** Utilizes a MySQL database managed via SQLAlchemy.
    *   **Cloud Integration:** Serves product images directly from an AWS S3 bucket via the backend API. Requires appropriate AWS credentials configured for the backend environment (e.g., EC2 instance role).
    *   **Configuration:** Uses environment variables (`.env` file) for sensitive keys (OpenAI API Key, Database credentials) and configuration (API Base URL).

## Tech Stack

- **Frontend**: React.js
- **Backend**: Flask (Python)
- **Database**: MySQL
- **AI**: OpenAI GPT-4 for chat and recommendations, CLIP for image similarity search
- **ORM**: SQLAlchemy

## Setup and Running with Docker (Recommended)

This is the easiest way to get the application running, as it manages the database, backend, and frontend services.

### 1. Clone the repository

```bash
git clone <repository-url> # Replace with the actual repository URL
cd palona-ai-task
```

### 2. Configure Environment Variables

Create a `.env` file in the project root directory (`palona-ai-task/`). This file will be used by Docker Compose to configure the services.

```dotenv
# --- Backend Configuration ---
OPENAI_API_KEY=your_openai_api_key_here # Replace with your OpenAI API key
# API_BASE_URL=http://localhost:5001 # Optional: Base URL for backend (if different from default)

# --- Database Configuration (for backend) ---
# These should match the MySQL service settings in docker-compose.yml
DB_HOST=mysql
DB_PORT=3306
DB_USER=palona
DB_PASSWORD=palonapassword
DB_NAME=palona_shop

# --- Frontend Configuration ---
# The frontend needs to know where the backend API is running inside Docker
REACT_APP_API_URL=http://localhost:5001 # Use the host machine's localhost and backend port

# --- MySQL Root Password (for initial setup) ---
MYSQL_ROOT_PASSWORD=rootpassword # Choose a secure root password
```

**AWS Credentials:** Ensure your AWS credentials are configured in the environment where you run `docker-compose up`. The backend service needs access to the S3 bucket specified in `backend/src/agent.py` and `backend/src/main.py` (currently `danieldoescode-s3`). Common methods include:
   - Configuring `~/.aws/credentials` and `~/.aws/config` files.
   - Setting AWS environment variables (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_REGION`).
   - If running on EC2, attaching an IAM role with S3 read permissions to the instance.

### 3. Build and Run the Application

From the project root directory (`palona-ai-task/`), run:

```bash
docker-compose up --build -d
```

*   `--build`: Forces Docker Compose to build the images for the frontend and backend based on their respective Dockerfiles.
*   `-d`: Runs the containers in detached mode (in the background).

This command will:
1.  Pull the official MySQL image.
2.  Build the `palona-backend` image using `backend/Dockerfile.backend`.
3.  Build the `palona-frontend` image using `frontend/Dockerfile.frontend`.
4.  Start the MySQL, backend, and frontend services.
5.  The backend will automatically attempt to connect to the database and build the FAISS image index on startup.

### 5. Access the Application

*   **Frontend:** Open your browser and navigate to `http://localhost:3000`.
*   **Backend API:** The API is accessible at `http://localhost:5001` (e.g., `http://localhost:5001/api/health`).

### Managing Docker Services

*   **Stop Services:** `docker-compose down`
*   **View Logs:** `docker-compose logs -f <service_name>` (e.g., `docker-compose logs -f palona-backend`)
*   **Restart Services:** `docker-compose restart`
*   **Access MySQL:** `docker-compose exec mysql mysql -u palona -p palonapassword palona_shop`

## Local Development Setup (Alternative)

Follow these steps if you prefer to run services directly on your host machine without Docker (except potentially for the database).

### 1. Clone the repository

```bash
git clone <repository-url>
cd palona-ai-task
```

### 2. Set up MySQL Database

#### Using Docker (Recommended)

```bash
# Make the setup script executable
chmod +x docker-setup.sh

# Run the setup script
./docker-setup.sh
```

This script will:
- Create the necessary .env file
- Start a MySQL container
- Configure the database for the application


### 3. Set up the backend

```bash
# Navigate to the backend directory
cd backend

# Create a virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt
```

### 4. Configure Backend Environment Variables

If you're using Docker, the setup script creates this file automatically.
Otherwise, create a `.env` file in the backend directory:

```
# OpenAI API Key
OPENAI_API_KEY=your_openai_api_key_here

# Database Configuration
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_mysql_password
DB_NAME=palona_shop
```

### 5. Initialize the Database

```bash
# Navigate to the src directory
cd src

# Run the database initialization script
python db_init.py
```

### 6. Set up the frontend

```bash
# Navigate to the frontend directory
cd ../../frontend

# Install dependencies
npm install
```


### 7. Running the Application Locally

#### 1. Start the backend server

```bash
# From the backend directory, with the virtual environment activated
cd backend
source venv/bin/activate  # On Windows: venv\Scripts\activate
cd src
python main.py
```

The backend server will start at http://localhost:5001.

#### 2. Start the frontend development server

```bash
# From the frontend directory
cd frontend
npm start
```

The frontend will be available at http://localhost:3000.

## API Documentation

The backend exposes the following RESTful API endpoints under the `/api` prefix:

*   **`GET /api/health`**
    *   Description: Checks the health of the backend service, including the availability of the OpenAI API key.
    *   Response: JSON object with status (`ok` or `warning`) and details.
*   **`POST /api/chat`**
    *   Description: Handles user chat messages. Analyzes intent, extracts entities/descriptions, interacts with OpenAI, searches the database, and returns a structured response including text and potential product recommendations.
    *   Request Body: `{ "message": "user query text" }`
    *   Response: JSON object containing `text` (chatbot response) and `recommendations` (array of product objects if applicable).
*   **`POST /api/recommend`**
    *   Description: Handles text-based product recommendations based on a query string. *Note: The current frontend primarily uses the `/api/chat` endpoint which incorporates recommendation logic.*
    *   Request Body: `{ "query": "user query text" }`
    *   Response: JSON object containing `recommendations` (array of product objects).
*   **`POST /api/search_by_image`**
    *   Description: Searches for products visually similar to an uploaded image.
    *   Request Body: `multipart/form-data` with an `image` file.
    *   Response: JSON object containing `results` (array of similar product objects with similarity scores).
*   **`GET /api/products`**
    *   Description: Retrieves all active products from the database.
    *   Response: JSON object containing `products` (array of all product objects).
*   **`GET /api/products/<product_id>`**
    *   Description: Retrieves details for a specific product by its ID.
    *   Response: JSON object representing the product, or a 404 error if not found.
*   **`GET /api/categories/<category_id>/products`**
    *   Description: Retrieves products belonging to a specific category ID.
    *   **Note:** The current backend implementation attempts to query the database using the category *ID* passed as an integer, while the underlying database function (`get_products_by_category`) expects a category *name*. This endpoint likely requires code adjustments in `backend/src/main.py` or `backend/src/database.py` to function correctly based on whether filtering by ID or name is intended.
    *   Response: JSON object containing `products` (array of product objects in the specified category).
*   **`GET /api/images/<filename>`**
    *   Description: Serves a product image file by proxying it from the configured AWS S3 bucket. Requires S3 access configured in the backend environment.
    *   Response: The image file content with the appropriate content type.

```bash
USE palona_shop;
```

```bash

```

```bash
docker-compose up -d
```



### OpenAI API Issues

If OpenAI API calls fail:

1. Verify your API key in the `.env` file
2. Check that you have sufficient credits on your OpenAI account
3. The application will fall back to a file-based catalog if OpenAI is unavailable
